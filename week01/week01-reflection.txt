GitHub link: https://github.com/lucas-lab2/CSE-341-Web-Services/blob/main/week01/src/db/connect.js

5.b. How did you store sensitive data? Why is that approach important?

Answer: Sensitive credentials such as the database connection string (MONGODB_URI) and database name (MONGODB_DB_NAME) are stored in environment variables, referenced in local development via a `.env` file and configured in Render's environment settings in production. The `.env` file is excluded from version control via `.gitignore`. This is essential because hardcoding credentials in source code exposes database access to anyone viewing the repository, leading to severe security vulnerabilities.

6.a. Include a GitHub link to a file that shows one other implementation decision you made.

GitHub link: https://github.com/lucas-lab2/CSE-341-Web-Services/blob/main/week01/src/controllers/booksController.js

6.b. What decision does this file show, and why did you make that choice?

Answer: This file shows separating the controller logic into a dedicated controller file (`booksController.js`) rather than placing business logic directly inside route definitions (`books.js`), as well as wrapping database calls in `try...catch` blocks that return explicit HTTP status codes (200 OK for successful queries, 404 Not Found when a book ID is invalid, and 500 Internal Server Error for database failures). This adheres to the Single Responsibility Principle and MVC architecture, making the application modular, maintainable, and robust.
